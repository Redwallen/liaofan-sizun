# 《了凡四训》互动学习网站 —— 内容编写规范

你要为《了凡四训》的一个互动学习网站编写「逐句对照解读」数据。目标读者是**完全不懂文言文**的现代中文读者，他希望通过一点点点击，逐句读懂原文。

## 输出格式

写一个 **UTF-8 编码的 JSON 文件**（不要 markdown 代码围栏，不要注释，不要尾随逗号），结构如下：

```json
{
  "chapter": 1,
  "title": "立命之学",
  "subtitle": "一句话概括本章（8-14字，可取自原文金句）",
  "intro": "本章导读，3-5句现代汉语，告诉读者这一章在讲什么、为什么重要。",
  "sections": [
    {
      "id": "ch1-s01",
      "title": "小标题：用现代汉语概括这一段（6-16字）",
      "pairs": [
        { "orig": "原文的一句话或一个完整分句。", "trans": "对应的现代汉语翻译。" }
      ],
      "notes": [
        { "term": "原文中出现的词", "explain": "现代汉语解释。冷僻字请标注拼音，如「髯（rán）」。人名、地名、典故、官职、年号务必解释。" }
      ],
      "insight": "1-3句话的点拨：这段话在全书中的意义、作者的用意、或对今天的启发。要具体、诚实，不要空泛说教，也不要复述译文。"
    }
  ]
}
```

可参考同目录下的 `_TEMPLATE.json` 示例。

## 硬性要求

1. **原文必须逐字照抄**你拿到的源文件，不得增删改任何字。按顺序、无遗漏地覆盖源文件全部内容。
2. **切分粒度要小**：每个 section 约 2-6 句（`pairs` 的条目数），让读者一次只需理解一小段。原文很长的地方要拆开，不要出现超长 section。
3. **`pairs` 的切分**：以原句为单位。原文中的长句可以按语义再切成 2-3 个分句，但 `orig` 拼接起来必须与源文完全一致（含标点）。引号、书名号等标点保持原样。
4. **译文要地道、清楚**：用自然流畅的现代汉语，不要文白夹杂，不要逐字硬译。人名、地名、官职可直接保留，必要时在译文里补出主语或语境（用括号补注亦可，但要克制）。
5. **注释（notes）** 每节 3-6 条，只收真正难懂的词。不要给「我」「人」这类常用字做注。对成语、典故、书名（如《易》《书》《孟子》）、历史人物、官职、年号、地名，必须解释。多音或生僻字加拼音。
6. **`insight` 要有信息量**：点出这段话的「为什么」，避免「我们要好好学习」这类空话。
7. **`id` 前缀见分配**，从 `s01` 开始连续编号，不要跳号。
8. **不遗漏、不重复**：写完后自己核对一遍，源文每一句都要出现在某个 `pairs` 里。

## 特别注意

- 原文中的括号夹注（如「丁卯年(公元1567年)」）是 EPUB 编者加的公元纪年，**照抄保留**，可在 notes 里说明。
- 不要自行添加源文里没有的句子。
- 输出的 JSON 要能被 `JSON.parse` 直接解析。
